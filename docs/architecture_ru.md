# Архитектура пайплайна

## Почему основной сигнал — это текст

Для телефонного мошенничества ключевой паттерн находится в содержании разговора:

- давление через срочность
- ссылки на государственные органы или службы безопасности
- просьбы назвать код, пароль, реквизиты
- истории про кредит, безопасный счёт, замену сим-карты

Поэтому в проекте текст выступает главным источником признаков, а аудио используется только как лёгкий статистический контекст.

## Почему нужен словарь триггеров

Небольшой датасет плохо прощает слишком сложные модели. Словарь триггеров даёт:

- интерпретируемые признаки
- устойчивость на маленькой выборке
- возможность быстро расширять правила без переписывания кода

Триггеры вынесены в `configs/triggers.yaml` по категориям:

- `authority`
- `money`
- `verification`
- `urgency`
- `credit`
- `sim`
- `relative_emergency`

## Зачем нужны regex features

Один и тот же смысл после ASR может выглядеть по-разному. Простое сравнение строк недостаточно, поэтому поверх словаря добавлены regex-паттерны:

- `код + смс`
- `переведите + деньги`
- `служба + безопасность`
- `мвд / полиция / прокуратура / центробанк`
- `срочность`
- `кредит`
- `сим / договор / госуслуги`

Это компромисс между жёсткими правилами и полной свободой TF-IDF.

## Почему baseline — LogisticRegression

`LogisticRegression` хорошо подходит для:

- sparse TF-IDF признаков
- маленького корпуса
- интерпретации коэффициентов
- быстрого локального обучения

В baseline используются:

- word TF-IDF `(1, 2)`
- char TF-IDF `(3, 5)`
- trigger features
- pattern features
- text meta-features

## Почему основной кандидат — CatBoost

`CatBoostClassifier` выбран как основная tabular-модель, потому что:

- он хорошо работает на маленьких табличных датасетах
- устойчив к разным шкалам признаков
- удобно даёт feature importance
- не требует сложной ручной настройки

В текущей версии в `CatBoost` подаются только dense handcrafted features:

- trigger features
- pattern features
- text meta-features
- audio stats

Это сделано сознательно, чтобы не переусложнять проект.

## Почему аудио используется только как лёгкие признаки

Аудио в этой задаче полезно как дополнительный контекст:

- длительность
- плотность речи
- паузы
- грубая спектральная статистика

Но не как основной источник сигнала. Поэтому в проекте нет:

- CNN по спектрограммам
- wav2vec-классификаторов
- emotion recognition
- speaker diarization

Такие решения тяжелее, менее воспроизводимы и хуже подходят под текущий размер датасета.

## Как устроен ансамбль

Ансамбль строится очень просто:

```text
final_prob = 0.7 * prob_logreg + 0.3 * prob_catboost
```

Почему это работает:

- `LogisticRegression` сильна на TF-IDF и словах
- `CatBoost` хорошо использует компактные плотные признаки
- их ошибки не полностью совпадают

После объединения вероятностей отдельно подбирается threshold для класса `Fraud`.

## Почему нужен group-based split

В датасете есть серии файлов вида:

- `out_a_13.wav`
- `out_a_14.wav`
- `Nout_b_33.wav`

Если случайно разделить данные по файлам, а не по сериям, получится утечка: модель увидит очень похожие записи одной и той же серии и на train, и на validation. Поэтому:

- из имени файла извлекается `group_id`
- валидация строится через group-based holdout

Это важнее любой косметической прибавки в метриках.
